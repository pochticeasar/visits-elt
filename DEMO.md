# Как показывать лабу (10 минут)

## До защиты (за 5 минут)

```bash
cd ~/projects/pirsbd/hasd/etl
docker compose up -d          # поднять garage, jupyter, airflow
docker compose ps             # все три — Up
```

Открыть 4 вкладки:

| Вкладка | Адрес |
|---|---|
| Airflow | http://localhost:8090 (`admin` / `admin`) |
| Jupyter | http://localhost:8888 → `notebooks/analytics.ipynb` |
| Отчёт | `report/report.md` (в VS Code: Cmd+Shift+V) |
| Код | `jobs/transform.py` |

Garage (порт 3900) в браузере не открывать: у него нет веб-интерфейса, он ответит `AccessDenied`.
Содержимое S3 показывать командами из шага 7 или таблицей слоёв в ноутбуке.

В Jupyter заранее нажать **Run → Run All Cells**, это ~3 мин. Иначе на защите не будет графиков.

Если что-то сломалось, запасной вариант: `report/analytics.html`. Там ноутбук со всеми результатами.

## Сценарий

### 1. Задача и схема (1 мин)

Сказать:

> «Задание: ELT-пайплайн. Extract готов: файл `visits_v1.tsv` на диске, 2.5 ГБ, 1.7 млн строк,
> 181 колонка. Load кладёт его в S3 в сжатом виде. Transform превращает его в формат для аналитики.
> Аналитика — в Jupyter».

Показать схему из README:

```
visits_v1.tsv ──load──▶ s3://raw ──transform──▶ s3://warehouse ──▶ Jupyter
                 └──────── Airflow: visits_elt ────────┘
```

Стек: Garage (S3), Spark, Jupyter, Airflow. Всё в Docker (`docker-compose.yml`).

Если спросят про слои: «Это медальонная архитектура. raw — бронза, данные как есть, только сжаты.
warehouse — серебро, очищенные данные. Золото — агрегаты, их считаю в ноутбуке».

### 2. Запуск пайплайна в Airflow (2 мин)

1. Airflow → DAG `visits_elt` → **Graph**: две задачи `load → transform`.
2. Нажать ▶ **Trigger DAG**.
3. Пока идёт `load` (~30 с), сказать:

> «Load читает TSV потоком, режет на 13 частей по 131 тыс. строк и пишет каждую в Parquet со сжатием zstd.
> Значения не меняю, все колонки храню как байты: в данных есть битый UTF-8.
> Было 2.5 ГБ, стало 453 МБ».

4. Кликнуть `load` → **Logs**: видны строки `part-00000.parquet: 131072 rows -> 34 MB` и итог.
5. Пока идёт `transform` (~45 с), открыть `jobs/transform.py` и пройти 4 пункта (см. шаг 3).
6. Задачи стали зелёными, в логе `transform` строка `visits: 1676581 rows`.

### 3. Transform: что и зачем (2 мин)

Показывать по коду `jobs/transform.py`:

| Что | Где в коде | Зачем |
|---|---|---|
| Типы: текст → числа, даты; `0000-00-00` и `''` → NULL | функция `typed` | не парсить текст в каждом запросе; у чисел в Parquet есть min/max |
| Массивы `[1,2]` → `array`, цели → массив структур | `typed`, `typed_visits` | одна цель — одна запись, а не 6 параллельных массивов |
| Схлопывание по `Sign` | функция `collapse` | в данных есть отмены (`Sign = -1`), иначе визиты считаются дважды |
| Партиции по дню, сортировка по счётчику, zstd | `main` | фильтр по дню читает одну папку; меньше места |

### 4. Один визит через все слои (1.5 мин)

Ноутбук, раздел 2. Это самое наглядное место.

- **TSV:** у визита 3 строки: отмена (`-1`), версия (`+1`), ещё одна версия (`+1`).
- **raw:** те же 3 строки, те же байты, плюс `_part`/`_row` (откуда строка).
- **warehouse:** 1 строка, последняя версия. Типы настоящие, цели — массив из 10 структур.

Сказать:

> «Так выглядит переход между слоями: в raw данные как есть, только сжаты;
> в warehouse — типы, структура и схлопнутые версии».

### 5. Аналитика (1.5 мин)

Ноутбук, раздел 3. Пролистать и назвать по одному выводу:

- будни ~260 тыс. визитов в день, выходные на 22% меньше;
- поиск даёт 27% визитов, прямые заходы 22%;
- на мобильных отказов больше: 41% против 30%;
- 10% визитов достигают хотя бы одной цели;
- тепловая карта: пик днём в будни.

### 6. Сжатый против несжатого (1.5 мин)

Ноутбук, раздел 4, таблица. Сказать:

> «Те же 7 запросов я выполнил по исходному TSV и по warehouse.
> По TSV каждый запрос заново разбирает текст, ставит типы и схлопывает: 3–10 секунд, читает 2.5 ГБ.
> По warehouse 0.2–0.5 секунды, читает 3–26 МБ, потому что Parquet читает только нужные колонки.
> Ответы совпали во всех 7 запросах: transform данные не исказил».

| | TSV | warehouse |
|---|---|---|
| Размер | 2534 МБ | 448 МБ |
| Время запроса | 3–10 с | 0.2–0.5 с |
| Читается | 2.5 ГБ | 3–26 МБ |

### 7. Показать данные в S3 (по желанию, 30 с)

```bash
docker compose exec garage /garage bucket list
docker compose exec garage /garage bucket info raw
docker compose exec garage /garage bucket info warehouse
```

## Вопросы и ответы

**Почему Parquet?**
Колоночный формат: читаются только нужные колонки. Внутри есть min/max по блокам, чтобы пропускать лишнее. zstd сжимает в 5.7 раза.

**Почему raw тоже Parquet, а не исходный TSV?**
Задание требует хранить в сжатом виде. При этом значения в raw не тронуты, из него можно заново сделать transform.

**Почему все колонки в raw — байты?**
В данных есть невалидный UTF-8, строковый тип его не примет. Типы — работа transform.

**Что такое `Sign`?**
Данные выгружены из ClickHouse-таблицы CollapsingMergeTree. Обновление визита пишется двумя строками:
«−1 старая версия» и «+1 новая». Без схлопывания визиты считаются дважды.

**Как схлопываешь?**
Ключ `(counter_id, start_date, user_id, visit_id)`, как сортировка в ClickHouse. Беру группы, где `sum(Sign) > 0`,
и из них последнюю строку с `+1`. Колонки с версией нет, поэтому «последняя» значит последняя по порядку в файле.

**Почему не просто `(CounterID, VisitID)`?**
У сотен разных визитов `VisitID = 0`. С ключом из 4 полей сумма `Sign` в каждой группе ровно 0 или 1.

**Почему партиции по дню?**
В данных 7 дней, получается ~64 МБ на партицию. Это нормальный размер файла для Spark. Мельче было бы слишком много маленьких файлов.

**Зачем сортировка по счётчику?**
Строки одного счётчика лежат рядом, и min/max в блоках Parquet узкие. Фильтр по счётчику пропускает лишние блоки.

**Что будет, если запустить пайплайн дважды?**
Ничего не задублируется. load пишет те же файлы и удаляет лишние, transform перезаписывает партиции.

**Зачем Airflow?**
Порядок шагов, повторы при ошибке (`retries`), запуск по кнопке и логи каждого шага в одном месте.

**Почему Garage, а не MinIO?**
Garage лёгкий и S3-совместимый. Community-версию MinIO в 2025 году сильно урезали.

## Если что-то сломалось

| Что | Что делать |
|---|---|
| Контейнер не Up | `docker compose up -d`, затем `docker compose logs <сервис>` |
| `NoSuchBucket` / `AccessDenied` | `./garage/init.sh` |
| Ноутбук пустой или сломан | `docker compose exec -w /work/notebooks jupyter python3 build_notebook.py`, потом Run All |
| DAG не виден в Airflow | подождать 30 с, обновить страницу |
| Нет времени ждать | показать `report/analytics.html` и `report/report.md` |
